    The short answer

    Yes, you need image models, but not as the renderer. On an 8 GB M1 nothing diffusion-based runs at interactive speed. So split it in two. A cheap 3D proxy gives you real-time drag, light and camera. The image models run once per asset (cutouts, outfits, 3D meshes) and once per hero frame (relight and harmonise), off the main loop.

    Decision rules this mode adds

    R10Person photo → cutout + normals (T1, M1) → card. Prop photo → image-to-3D (cloud) or a Blender asset → mesh.
    R11A card viewed more than 35° off its axis → flag it. Upgrade to a mesh or limit the orbit. Live here: turn off “Cards face camera” and orbit.
    R12Outfit or appearance change → edit model with the identity reference (T2, cloud), then a face-similarity check (T1) before it is accepted.
    R13Look match under 85% after refinement → escalate to a hero pass, or to you (T3). Live here.
    R14Plate light contradicts the key (shadows point the wrong way) → de-light the plate, or move the key to agree with the plate.

    What will go wrong

    • The plate already has light in it. Move the key and the baked window light still points the old way. Try “Relit plate” off and on.
    • Cards are paper. A cutout holds up to roughly 35° of orbit. Past that you need a real mesh.
    • Identity drifts. Every outfit edit and every hero frame can change the face. The edit model needs the person's reference image, and a face check decides whether to accept.
    • Contact shadows need contact. Feet that float a few centimetres read as fake, so the floor and the footprint matter more than the model.
    • Video flickers. Per-frame diffusion is not temporally stable. Use the proxy for motion and the image model for stills and keyframes.
    • Licences differ per model. Check each one, including any territory or commercial limits, before client work.

    1. Scene graph and viewerThis prototype. Test: JSON round-trips, transforms, match metric recovers a known light on synthetic scenes.
    2. Ingest CLI on the M1Photo → cutout + depth → card asset + JSON. Test: mask IoU against 10 hand-masked photos.
    3. Cloud asset jobsOutfit edit and image → 3D behind a job queue, with a cache and a cost log. Test: face-similarity gate.
    4. Real reference matchingTab 1's fit drives the rig from real footage. Test: Blender scenes with known lights.
    5. Hero passRelight / harmonise on demand. Test: blind A/B against the proxy.
    6. Blender bridgeExport glTF or USD and render finals in Blender when a client needs it.
