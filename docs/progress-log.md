## PR-LL-002 · 2026-09-30 — **P2: the breakdown measures real pixels** (deterministic, no AI)

**Suite: 193 passed / 0 failed across 18 files (`npm test`, which builds the UI first; two files run in Chrome); `npm run typecheck` clean.** Baseline at the start of the session: 90 / 0 across 10 files. Coverage of core, contracts, actions and engine: 94.8% statements, 96.3% lines, 83.4% branches. No model API and no FFmpeg anywhere.

- **Import (D-LL-027, AD-LL-007).** Drop an image or video on Breakdown (or ⌘K → the drop zone). Chrome decodes it, hashes the file in 8 MB pieces (SHA-256), samples 2 frames per second at ≤ 512 px and sends each as PNG through `breakdown.add_frame` (bodies ≤ 2 MB; every other action keeps 1 MB and oversized bodies now get 413). The engine keeps the file's name, type, size, date and hash, never the file or its path, and stores the frames beside the reference. It reads PNG with its own `node:zlib` decoder (D-LL-031). The store gained binary files (AD-LL-005 seam).
- **Instruments in `src/core/`, DOM-free and Node-free (AD-LL-009):** CIELAB and CIEDE2000, checked against Sharma's published pairs; palette by seeded k-means in Lab with 3 × 3 median sampling, near-duplicate merging and sliver folding (D-LL-024); contrast in stops from 2nd/98th linear-luminance percentiles with a 2^-10 floor, CIELAB saturation, shadow/mid/highlight tint (D-LL-025); letterbox detection and aspect from the active picture (D-LL-029); cuts from trilinear colour histograms with an adaptive threshold, so a fade is not a cut (D-LL-026); streamed SHA-256.
- **Actions:** 72 (57 commands, 15 getters and helpers; 19 stand-ins, down from 23). `breakdown.import_reference`, `detect_shots`, `sample_palette` and `analyse` are real, with their stand-in flags removed in the same change and tested. New, not commands (so the design-catalogue parity test still holds): `add_frame`, `get_frame`, `get_reference`, `set_subject` (subject position by hand, D-LL-028). MCP lists all 72 (tested). `fit_framing` now returns only what it would estimate (size, lead room). A saved look's source is its palette's; light and mood carry their own (D-LL-030).
- **Breakdown screen (D-LL-032, D-LL-015, D-LL-021):** every value renders from the engine record with its own badge: palette, tints, saturation, contrast and aspect read MEASURED; subject reads MANUAL after a click; light, lens and mood read SAMPLE, and the marker says exactly that. The frame, its thirds and the subject marker are drawn on the picture itself. Nine design literals became data through `bindings.json` (the drop hint had promised ProRes and TIFF, which Chrome cannot decode). The converter lets a screen fill an image slot by id; views were regenerated, not edited.
- **Verified in Chrome (tests):** the committed fixture `tests/fixtures/patches-239.png` imports through the file picker, its five colours read MEASURED within ΔE00 2 and 2 points of share, aspect 2.39:1; a click sets the subject; Save look → `library.list` returns the look as "measured" with light "sample". A clip recorded in the page (canvas + MediaRecorder) with cuts at 1, 3 and 9 s and a 3 s dissolve gives four shots, each cut within one sampled frame.
- **Measured on the M1 (8 GB), synthetic 60 s 1080p H.264 clip (117 MB), recorded in Chrome because no real 60 s clip was available; three runs:** import to breakdown 19.2 s, 19.2 s and 19.3 s (target ≤ 60 s): 2.4 s hashing, 15.8–15.9 s decoding and sending 121 frames, 0.9–1.0 s cuts and measurement; 8 shots found in 8 scenes. Engine RSS 136–137 MB idle before import, 146–148 MB peak during, 146–147 MB idle after (budget ≤ 150 MB: inside, with 3–4 MB to spare; P1 measured 121 MB idle). Tab JS heap 27.6–29.2 MB. One 512 × 288 frame: palette 33.5–49.1 ms, tone 25–26 ms, cut signature 0.7–0.8 ms. Frames on disk 29 MB per minute of video. Harness: `scripts/measure-import.ts`.
- **Found and fixed:** B-LL-002 (the recorded test clip gave a cut that was not there: Chrome's canvas recorder writes a file's first frame with different colours from the rest; decoding was checked and is consistent). The same run showed a black leader would become the measured frame, so the default is now the longest shot's key frame. The wiring test caught that `breakdown.sample_palette` was no longer called from the screen; the design's step order was restored.
- **Not done, stated plainly:** nothing was measured on real footage and no accuracy is claimed for it (standing rule 3); light, lens, framing size and mood remain sample (P3/P4); "Paste a link" on the drop zone opens the file picker (links are not supported); the design's frame box stays 2.39:1, so other shapes are letterboxed inside it; engine memory after a 60 s import is close to its 150 MB budget; Chrome is the only browser tested; `claude mcp add` was still not run against the founder's own Claude Code.
- Codebase at this entry: `src/` 56 hand-written files / 5,085 lines (views excluded), of which `src/core/` 791; `tests/` 22 files / 2,311 lines plus a 9.5 KB PNG fixture.
- Records touched: D-LL-024…D-LL-032 (new), B-LL-002 (new), AD-LL-005, AD-LL-007, AD-LL-009, D-LL-015, D-LL-021; `CONTEXT.md` (reference, sampled frame, cut, key frame, active picture), `architecture.md` §8, `phases.md` (P2 done).
